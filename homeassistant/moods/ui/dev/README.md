# ui/dev: testing the Moods UI off the phone

Nothing in this folder is loaded by the page, and none of it ships: the shell's `copyUiAssets` copies `ui/` into the APK without `ui/dev/`. It is only used on a computer. Everything here runs on Node 24 with no npm packages.

The contract is `docs/ARCHITECTURE.md`, section 3.

## The UI in one screen

| File | What it holds |
| --- | --- |
| `../index.html` | Markup, plus the first inline script: the `Shell.heartbeat()` interval, the `window.__shell` queue and `--u` |
| `../ember.css` | The whole look, with the bundled Fraunces `@font-face` rules |
| `../app.js` | Views, deck, hold, confirmation marks, Undo, night, brightness, shell events. **`BRIGHTNESS`, `TIMING`, `LUX` and `HEALTH` at the top are the tuning tables** |
| `../ha.js` | The Home Assistant WebSocket client and the entity store |
| `../moods.js` | Attributes to moods, palette checks, and the sky generator |
| `../glyphs.js` | The glyph set, keyed by `mood_glyph`, with the neutral `ember` fallback |
| `../sim.js` | A simulated Home Assistant, shared by mock mode and `fake-ha.js`. With the runner's tables passed in (`fake-ha.js`, the node checks) a custom mood slot runs its card's steps with `script.moods_custom_run`'s rules |
| `../mock.js` | Mock mode: the five demo moods as HA attributes (plus, with `mockset=custom`, two custom mood slots and placement), and an in-page socket over `sim.js` |
| `../fonts/` | Fraunces variable (roman and italic, latin and latin-ext woff2, axes opsz/wght/SOFT) and `OFL.txt` |

Modes: shell with a config; mock (no config, or `?mock=1`; shows a small "Demo" tag); browser direct (`?ha=ws://host:8123/api/websocket&token=...`).

Test parameters: `state=idle|deck|applied`, `mood=<index or slug>`, `night=1`, `static=1`, `demo=1`, `fps=1`, plus `time=HH:MM` (pins the clock and the night hours, for screenshots), `panel=`, `temp=<entity>` (a sensor, or a climate entity whose `current_temperature` is shown), and in mock mode `mockset=many` (twenty moods, several deliberately malformed), `mockset=custom` (the demo moods plus custom mood slot 1 "Reading", ready, and slot 2 "Dusk", switched off, with the cards Home Assistant renders, and placement: Movie Night "Not on the Bedroom Palm", Good Morning order 5; without the runner's tables mock mode applies a slot's card touches, as it does a built-in mood's; `mood=custom_1` starts on the slot), `never=<entity>` (the entity that never answers; default `light.role_patio_lights`), `outside=<seconds>` (another "phone" changes the mood on a timer) and `speed=` (multiplies the simulated delays). `state=applied` and `demo=1` change the house only in mock mode.

`window.__moods.info()` in the page returns the current state (view, connection, current mood, the deck's slugs and those kept only because they are current (`hiddenHere`), marks, brightness, notes). `window.__moods.trail` lists recent haptics, brightness levels, service calls and status changes. Neither holds the token or the config.

## The fake Home Assistant

```bash
node ui/dev/fake-ha.js                       # ws://127.0.0.1:8767/api/websocket, token "test-token"
node ui/dev/fake-ha.js --port 8768 --token t --never '' --outside 45 --initial focus --clock 07:30
node ui/dev/fake-ha.js --card-set ready      # custom mood slots 1 to 3 ready, slot 4 not ready
node ui/dev/fake-ha.js --old-house           # a house from before custom moods and placement
```

It parses the real mood files in `ha/packages/moods/` (with `mood-yaml.js`, a small reader for those files) and runs them on `sim.js`:

- **Protocol:** `auth` (a wrong token gets `auth_invalid` and the socket is closed), `supported_features`, `get_states`, `subscribe_entities` (`entity_ids` and/or `include`/`exclude`, the same filter rules as HA), `subscribe_events` (`state_changed`), `unsubscribe_events`, `call_service`, `ping`.
- **The same messages HA sends:** `subscribe_entities` change events are partial diffs, as in HA 2026.11. A script that runs sends only `s`, `lc`, `c` and the changed attributes (`last_triggered`, `current`). A client that replaces attributes instead of merging them loses `mood: true` here, just as it would on the real box.
- **Moods behave like the package:**
  - `mood_begin` refuses everything but Away in vacation mode, writing the notice.
  - Then it refuses a mood outside its `mood_window` (Good Morning, 05:00 to 11:00) with the package's reason, "Good Morning only runs between 05:00 and 11:00." Undo into it is refused the same way. The rule is `HouseSim.windowState` in `sim.js`, which mirrors the template in `moods_core.yaml`: `from` inclusive, `to` exclusive, midnight crossing, and a malformed window runs the mood (and is logged). The clock is real time unless `--clock HH:MM` or `/control/clock` pins it. In mock mode the page's `?time=` pins it.
  - It stops other running moods.
  - Each mood script is `mode: restart`: starting a mood that is still running stops its earlier run first, before `mood_begin` decides, so a re-tap that is refused (Good Morning tapped again after 11:00 while still rising) leaves the earlier run stopped, as in Home Assistant.
  - It moves current to previous, but not when the current mood is re-run.
  - The slug comes from the script's entity id, as in the package; `mood_slug` plays no part.
  - A `script.turn_on` on a missing script succeeds and does nothing (HA only logs it).
  - Each touch entity reaches its expected state after a realistic delay: lights 0.7 to 1.8 s, switches 0.5 to 1.3 s, mirrors (`binary_sensor`) 1.8 to 4 s, speakers 1.5 to 3 s.
  - `light.role_all_lights` follows the other light roles.
- **One entity never answers** (default `light.role_patio_lights`, Afterglow's and Hosting's Patio mark).
- **The settings helpers:** every helper the package defines exists as Home Assistant creates one with no `initial:`: an `input_select` at its first option, an `input_number` at its min, an `input_text` `unknown`, an `input_boolean` off (the house's own `house_mood` helpers are left alone). That includes every mood's placement helpers (`input_select.moods_<slug>_where` at "Usual (as the mood says)", `input_number.moods_<slug>_order` at 0) and the custom slots' helpers. Change one with `/control/set`, for example the bedroom panel's `input_select.moods_panel_bedroom_night_hours` or `input_select.moods_focus_where`, or remove it with `/control/remove`.
- **Custom mood slots:** the six slot scripts (`script.mood_custom_<n>`, customize `mood_slot`) come from the package, and `sensor.moods_custom_<n>` carries a card from `fixtures/custom-cards.json`: the set named by `--card-set` (default `empty`, every slot empty, as on day one, so the deck is the 0.1.0 deck; `ready`: slot 1 Reading, slot 2 Dusk with a 17:00 to 23:00 window, slot 3 Red room, all ready, slot 4 named but with nothing to do). The cards are the ones Home Assistant 2026.11.1 renders from the generated card body (`fixtures/make-cards.py` writes them; rerun it after a change to the card template in `gen-custom.js`). A slot is refused like the package's `mood_begin`: vacation first, then a card that is not ready (with its `mood_reason`), then the card's window (with its `mood_name`). Then it runs `script.moods_custom_run`'s rules with `gen-custom.js`'s tables: its own refusals, the steps mapped through the tables (no guest room, 1 to 100%, fade 0 to 60 s, one colour key), the off set built by exclusion (here a role is its own leaf, and `light.role_all_lights` the other light roles), and the TV, diffuser and bed. Each call it would make is listed by `/control/actions`, and each entity reaches its state after the usual delay. `--old-house` leaves out the slot scripts, the card sensors, the `custom_mood_*` helpers and every `_where`/`_order` helper.

Control endpoints on the same port:

| GET | Effect |
| --- | --- |
| `/control/state` | Current mood, previous, notice, connection count, every entity's state |
| `/control/calls` | Every `call_service` received (`?clear=1` empties the list) |
| `/control/drop` | Destroys every socket (no close frame), like a Wi-Fi drop |
| `/control/stall?ms=40000` | The sockets open now stop answering (pings included) and stay open: a half-open link. Their inbound messages are held and delivered when the stall ends, if the socket is still open. A socket opened during the stall is a fresh link: it gets `auth_required` at once and works normally, as with real HA |
| `/control/lag?ms=10000&for=2000` | What the sockets open now send during the next `for` ms reaches the phone `ms` late, in order (what follows waits behind it), while the phone's own messages reach HA at once: Wi-Fi holding inbound packets. A socket opened later is not lagged. With `&after=result` the window opens once the next call's answer has gone out on time: the answer arrives and the state diffs HA writes after it are held (pongs too, as TCP would) |
| `/control/refuse?ms=5000` | Refuses new connections, like HA restarting |
| `/control/outside?slug=focus` | Something else sets a mood (voice, the other phone); with no slug, a random one |
| `/control/never?entity=ID` | Changes the entity that never answers (`entity=` for none) |
| `/control/vacation?on=1` | Turns vacation mode on or off |
| `/control/clock?at=07:30` | Pins the house's local time (hours and minutes) that mood time windows are checked against; `at=` with no value goes back to real time. `/control/state` reports it as `clock` |
| `/control/remove?entity=ID` | Removes an entity (a helper that is gone) |
| `/control/set?entity=ID&state=S`, `/control/temp?value=71` | Set any state, or the temperature (`&entity=climate.thermostat` sets that thermostat's `current_temperature`; the fake always has one, in `heat_cool`) |
| `/control/noop?entity=script.mood_focus&on=1` | That mood script runs but never calls `mood_begin` (a file missing its first two steps): the call succeeds and `house_mood` never moves. `on=0` undoes it |
| `/control/reload?dir=PATH` | A script reload: removes every mood script (and slot script), then creates them again from `PATH` (default: the folder loaded at start). Use a copy of `ha/packages/moods` plus a new file to try a mood before deploying it |
| `POST /control/cards` | Replaces custom mood cards. JSON body `{"<slot>": V}`: `V` is a variant name from the cards file (`"reading"`, `"reading_off"`, `"dusk"`, `"red"`, `"idle"`, `"empty"`), `{"state": S, "card": C}` (any JSON, garbage included), or `null` (the sensor is removed). Slots not named are left alone. `?set=NAME` loads a whole set; `?slot=N&raw=TEXT[&state=ready]` makes the card attribute that text; `?slot=N&state=unavailable` makes the sensor unavailable and drops its card attribute, as Home Assistant does for a template entity that fails. GET works for the query forms |
| `/control/actions` | What the custom mood runner did, as service calls (`?clear=1` empties the list) |

`node ui/dev/mood-yaml.js --check [dir]` compares the reader with PyYAML (through `uv`) for every file in `dir` (default `ha/packages/moods`): the customize blocks and the `input_select:` helpers.

## Tools

The page needs a static server on port 8766 serving `ui/`, for example `python3 -m http.server 8766 -d ui`.

Then it holds, confirms, undoes, misses a mark, gets refused, sees an outside change, loses and regains the connection (dropped, refused and half-open, including a hold sent into a half-open link, a mood HA sets while its answer is 10 s late, or while its answer is on time and the diffs after it are 10 s late, staying on the face, a 4.5 s lag that delivers `house_mood_previous` alone keeping the face's Undo, and a face Undo under the same lags), gains and loses a mood through a script reload without a page reload, sends power, net and sensor events, and checks the night face (including a deck opened from the Lights Out night face staying at the night level), the five-tap escape and a thermostat as `tempEntity`. Time windows: it checks the window rule's boundaries in node, and on `sim.js` that a re-tap after 11:00 of a Good Morning still rising is refused and stops the earlier run (`mode: restart`), then, on the fake's pinned clock, that Good Morning is refused at 21:18 (vacation's reason wins when both apply), runs at 07:30, and that an Undo into it at 11:00 is refused. ## Adding to the look

- **A new glyph:** draw it in a 64x64 box, with round caps and the light source where the halo is, and add it to `glyphs.js` under its key. Moods using an unknown key show the neutral `ember` glyph meanwhile.
- **A new mood's palette:** `glows` are `[lamp, band, counter-light]`:
  - **Lamp:** the dominant low glow behind the lower centre (small and faint for a `mood_night` mood).
  - **Band:** a broad soft field high on the wall.
  - **Counter-light:** a faint glow in a corner; neighbouring cards use different corners. A grey one about as dark as the room is left out.

  Strength comes from luminance, so pale colours stay dim. `accent` colours the glyph, rings, marks and the "On now" flag; it is lightened only if its luminance is under 100. `ink` (optional) colours the clock and the name; without it a cream is derived from the accent. `base` is the room's dark plaster, darkened if too bright.
- **A hand-tuned sky:** `mood_palette.sky` replaces the generated one: up to four `[kind, "#rrggbb", alpha, width, height, x%, y%, drift]` layers (`kind` band, lamp or glow; sizes in u; drift 1 to 3), drawn in order. Values are clamped (alpha at most 0.62, and alpha times the colour's luminance at most 100). The five Ember moods carry their approved skies this way, in the package files and in `mock.js`; Focus carries a hand-tuned bright, cool one (its lamp is at about 89 of that 100). `lint.js` reports any package sky the UI would clamp.

  Check a new palette with `?mock=1`, or against the fake HA after adding the mood file.
